# Architecture

Soundlore at its core like any other `iced` application is a `view` function describing what should be displayed in the window, and an `update` function that handles user interactivity through the UI or through subscriptions. Beneath the UI layer there is a playback system that consists of two additional threads managed by the Playback Controller: The decode thread and the audio thread.

For persisting data we use SQLite and to interact with the database we use several free functions that simply consume a pool and parameters relevant to the query, migrations get run when starting the app and alongside these migrations we run a check that tracks how many migrations have been run in your database to prevent situations where a downgrade corrupts the database.
